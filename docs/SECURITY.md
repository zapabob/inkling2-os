# Security

The console binds to an explicit loopback address. The request boundary verifies Host, Origin, Fetch Metadata and body framing. Linux limits the console socket to the designated operator identity and root. The Windows launcher defaults to key-free local mode, which allows other local Windows processes to reach the port. The optional token mode provides separate console and inference access for shared systems and tunnels. Windows stores credentials for that mode through DPAPI. Chat text is not automatically written to Memory45.

Finder resolves the configured shared directory through a directory handle. It refuses path traversal, links, hidden and sensitive-looking names, and previews of model or companion state. Share a directory containing only documents intended for this console. The file type and name rules do not inspect the sensitivity of the text inside an allowed document.

The browser requests public IPv4 destinations over HTTPS port 443. It validates DNS results and pins every request, including each redirect. It renders documents in a sandboxed frame with a restricted HTML allowlist and routes links back through the same request path. Website scripts, forms, remote media, cookies and proxy configuration are outside the reader. RustXNG receives explicit search queries through a loopback port. Lookup results open through the reader.

Linux PID 1 loads the default-deny nftables policy before network setup. Public IPv4 HTTPS is reserved for the bridge and RustXNG service users, with narrow DNS, DHCP and NTP exceptions. If policy loading fails, PID 1 leaves the console and search offline. Finder uses the operator-managed `/var/lib/inkling2/files` directory, which the bridge can read and the operator and search identities cannot open directly. Root remains the system administrator. Ordinary processes retain standard Linux access to files outside this shared directory according to their Unix permissions.

The private USB exposes a separate native Tor Browser launcher. The local console account can request the launch through a FIFO. The browser runs under a dedicated UID with its own profile directory. Only that account receives the private image’s public TCP allowance for Tor relays. The console, search, and inference accounts cannot use the Tor SOCKS or control ports. The private image shares the workstation’s X11 session among its local graphical apps. Access to the physical console is the operator trust boundary.
