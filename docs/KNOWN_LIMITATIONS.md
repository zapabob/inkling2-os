# Known limitations

The Windows adapter runs the native process per admitted request. It uses the model's embedded template and Hugging Face tokenizer, and sends numeric token IDs to the CUDA process. Native generation currently supports plain-text messages with reasoning disabled and a 4,096-token engine context. It buffers the answer before emitting OpenAI-compatible events. Model-level accuracy and long-context qualification remain separate from tokenizer conformance.

The Linux engine builds for `sm_120a`. The private driver bundle, physical GPU-backed boot and model generation require qualification. Scheduler profiles, comparative performance and long context also require fresh measurements. The live ISO’s companion state is volatile. Dynamic LoRA remains an adapter-state experiment, without a confirmed model-weight update path.

The built-in Browser renders public IPv4 HTTPS documents and follows up to three validated redirects. Sites that require JavaScript, authentication, video or other active resources are outside the document reader. Finder exposes read-only previews of approved text files. The Windows console runs within Windows' existing network and filesystem policy. The Linux images provide a local terminal with a loopback HTTP service. The installed disk bundle requires UEFI and provides persistent storage. A graphical Linux desktop and graphical Wine session are still pending.
