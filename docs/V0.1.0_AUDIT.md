# v0.1.0 baseline audit

The published v0.1.0 tag resolves to `78bf6231d675c7f7b9f17d95190c29a7b53e0a23`. The release includes a Windows zip, an El Torito ISO file and checksums. The existence of those files supplies packaging evidence. Boot and inference require runtime evidence. [GitHub release](https://github.com/zapabob/inkling2-os/releases/tag/v0.1.0)

| Area | Confirmed from source |
| --- | --- |
| Boot image | GRUB requested a PID 1 executable located in SquashFS. The stock initramfs had no path to discover or mount that SquashFS. The image staging step omitted the Rust executables’ dynamic dependencies and several helpers. |
| PID 1 | The executable respawned an interactive shell with fixed delays. It lacked bridge health checks, a restart ceiling and process-group shutdown. |
| GPU and RAM | The tier planner used fixed VRAM and HugePages values. Dry runs incremented operation counters without kernel side effects. The ISO staged no matched NVIDIA kernel modules, firmware, or CUDA runtime. |
| CUDA and I/O | The C++ Linux target produced a static runtime library. The independent engine was built around Win32 libraries and Windows process/I/O code. There was no linked Linux decoder in the boot image. |
| Console | The bridge allowed unauthenticated operations by default and used a JSON substring scanner. Its fallback could display a synthetic response. Browser and file-preview work was already present as uncommitted changes at intake. |
| Companion | Memory45 and LoRA had local state operations. The examined LoRA adapter had no model-weight integration, and the bridge implicitly inserted chat text into memory. |
| CI | The release workflow built Rust packages. It did not build or boot the ISO or verify CUDA generation. |

The initial standalone CUDA checkout was clean at `6faa017e596179eeb25037c0b70d793bda9b68d9`. It contained a Windows CMake build, a release workflow, and one native test executable target. The working Strata checkout was at `c99ade621e1b6852a8abab8316d88b9c9f0bca16`, with local changes and diverging main history. The remote main read back as `eaa8ac178ca2d318337493ce455607b5f6b3bcf4`. The installed user-facing application reported version 0.8.6. All three projects carry an MIT repository licence. Strata integration uses its installed custom-provider interface.
